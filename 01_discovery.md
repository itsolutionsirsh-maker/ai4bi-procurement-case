## 1.2. Скоуп первого релиза (4 недели)

**Цель релиза:** Смирнов и Ковалёва открывают в AI4BI три экрана на живых данных 1С и WMS и верят цифрам, потому что видят, как они посчитаны и почему сходятся (или не сходятся) с финансами.

### Входит

| Что | Результат для заказчика |
|---|---|
| Загрузка из реплики 1С (заказы, строки, справочники, курсы) и из Kafka `wms.receipts.v1`, ночное обновление 1С + приёмки в течение дня | Данные без ручного Excel. Ночная загрузка вместо трёх дней работы Даши |
| Модель данных: мастер-поставщик (склейка по ИНН), SCD2 поставщика, курсы, ЕИ, флаги качества | Один поставщик = одна строка в отчётах |
| **Экран 1. OTIF**: единое определение (согласовано Смирновым письменно), рейтинг поставщиков внутри класса с доверительным интервалом (на полугодовой истории различия между поставщиками пока в пределах шума), динамика по месяцам, разложение на On-Time и In-Full | Одна цифра вместо 94% и 71%, с объяснением, откуда были обе |
| **Экран 2. Цены**: средневзвешенная цена за единицу в разрезе категорий, отклонение от медианы других поставщиков, отклонение от плановой цены. Показываем заказчику после ответов 1С по ЕИ и валюте (вопросы 4–5): на текущей выгрузке сравнение цен — шум | «Эту гайку у одного по 12, у другого по 19» и сумма переплаты |
| **Экран 3. Оборот и сверка**: оборот по поставщикам и категориям, концентрация, сверка «заказано / принято» с отчётом финансов за 2025 год | Объяснение расхождения 8–10% по статьям |
| **Качество данных**: дубли, позиции без карточки, проблемы ЕИ и валют, свежесть данных на каждом экране | Видно, где цифрам можно верить, а где ждём ответа от 1С |
| Вопросы на русском по этим трём витринам (если ответ на вопрос 10 позволяет): 20–30 эталонных вопросов, проверенных вручную | «Покажи, где выросла цена за квартал» без ожидания аналитика |

| Хотелка | Решение | Почему |

| Расхождение с финансами 8–10% (Смирнов) | **Сейчас** | Без сверки нет доверия ко всему остальному. Гипотеза уже есть |
| Цена за единицу по категориям (Ковалёва) | **Сейчас**, с оговоркой | Зависит от ответа по ЕИ (вопрос 4). До ответа сравнение идёт внутри одной ЕИ закупки |
| Спросить по-русски (Ковалёва) | **Сейчас**, если позволяет инфраструктура (вопрос 10); иначе этап 2 | Это суть AI4BI, но в закрытом контуре нужна модель внутри периметра |
| Договоры и тендеры из SRM | **Отдельный этап (недели 5–7, 14.09–02.10, до правления)** | API без инкремента для тендеров и с поштучными лотами. Первичная загрузка занимает дни. Зато к правлению получаем «цена по договору vs факт» |
| Прайсы поставщиков из почты (Excel в разных форматах) | **Отдельный этап (после правления)** | Нужен разбор каждого формата (LLM-извлечение + проверка человеком). Это отдельный продукт, см. `07_account.md` |
| Предсказание срыва поставки (Смирнов) | **Отдельный этап, не раньше чем через 3–6 месяцев эксплуатации** | Прогнозировать нечего, пока нет согласованного OTIF и чистой истории: сейчас даже факт срыва считается тремя способами. На первом этапе даём ранний сигнал правилами: поставщик с падающим OTIF, просроченные строки без приёмки |
| Цены конкурентов с маркетплейсов (Ковалёва) | **Не делаем** | Контур закрытый, наружу интернета нет. Розничные цены маркетплейсов несопоставимы с B2B-закупками промышленных расходников (объём, договорные скидки, доставка). Парсинг нарушает правила площадок и ломается при каждом изменении вёрстки. Альтернатива: медиана цен по нашим же поставщикам (уже в экране 2) и, при желании, лицензированный ценовой источник через согласованный шлюз |

## 1.3. Три главных риска

| # | Риск | Вероятность | Влияние | Митигация |
|---|---|---|---|---|
| 1 | **Цифрам не поверят.** Данные грязные (дубли контрагентов, ЕИ, валюты, версии строк). Любое расхождение с привычным Excel или с финансами дискредитирует систему, как сейчас дискредитирован Excel | Высокая: дефекты уже найдены в выгрузке | Высокое: если директор не верит, проект не продлят | 1) Определения метрик Смирнов подписывает письменно до разработки экранов (неделя 1). 2) На каждом экране статус качества данных и свежести; спорные строки помечены, а не спрятаны. 3) Сверка с финансами за 2025 год по статьям («заказано → принято → оплачено») до показа директору. 4) Еженедельный 30-минутный разбор DQ-отчёта с Пономарёвым: он решает по склейке и ЕИ, мы применяем правило в пайплайне |
| 2 | **Доступы и закрытый контур задерживают старт.** Реплика 1С, Kafka ACL, место развёртывания, LLM внутри периметра. Каждый пункт — отдельная заявка в ИТ, и сроки по ним не в наших руках | Высокая | Высокое: 4 недели — это 20 рабочих дней, неделя ожидания = −25% срока | 1) Список доступов с датами в письме Смирнову сразу после встречи (`06_letter.md`), с владельцем каждого пункта у заказчика. 2) Разработка не ждёт доступов: модель, трансформации и тесты уже работают на выгрузке Пономарёва; доступы нужны только чтобы переключить источник. 3) Kafka: если retention короткий или ACL задерживается, история приёмок берётся из БД WMS выгрузкой, а топик подключаем для новых событий. 4) LLM: если GPU или модели в контуре нет к неделе 2, вопросы на русском переносятся в этап 2, а дашборды выходят по плану. Решение фиксируется на неделе 2, а не на неделе 4 |
| 3 | **Ожидания разъедутся со скоупом.** Предсказание срывов, маркетплейсы, «работающее на правлении через 8 недель». Без явных договорённостей к неделе 4 заказчик ждёт ИИ-прогноз, а получает дашборды | Средняя | Высокое: релиз будет воспринят как провал даже при выполненном скоупе | 1) Скоуп и «не делаем, почему» фиксируются письмом и подтверждаются ответом Смирнова (`06_letter.md`). 2) Демо каждую пятницу: заказчик видит прогресс, а не презентацию в конце. 3) На любую новую хотелку — оценка и выбор «вместо чего» или «в этап 2», без молчаливого добавления. 4) Этап 2 (недели 5–7) сразу собирается вокруг трёх вопросов правления (вопрос 12), чтобы у директора была понятная дорога к правлению |
